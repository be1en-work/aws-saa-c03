## Sesión 10.1 — CloudFront

### Slide 1 — Amazon CloudFront

**Título en slide —** AMAZON CLOUDFRONT

#### Nombres en portal y examen

> **Amazon CloudFront** — **edge location** — **origin**

#### Conceptos

- **Amazon CloudFront —** Content Delivery Network de AWS para contenido HTTP y HTTPS.
- **Edge —** el usuario se conecta a una ubicación cercana de la red global de AWS.
- **Cache hit —** CloudFront entrega el contenido desde caché sin consultar al origin.
- **Cache miss —** CloudFront obtiene el contenido desde el origin y puede almacenarlo para solicitudes posteriores.
- **Origin —** puede ser Amazon S3, un load balancer u otro servidor HTTP compatible.

> **Nota —** Un custom origin puede estar incluso fuera de AWS, como un servidor web on-premises accesible mediante HTTP o HTTPS.

**Docs —** Amazon CloudFront Developer Guide — What is Amazon CloudFront?

**Idea visual —** icono oficial de **Amazon CloudFront** como elemento principal. Usuarios de dos continentes llegan a diferentes edge locations. Un `Cache hit` termina en el edge; un `Cache miss` continúa hacia un origin.

### Slide 2 — Cache behaviors y varios origins

**Título en slide —** CACHE BEHAVIORS — VARIOS ORIGINS

#### Nombres en portal y examen

> **Cache behavior** — **path pattern** — **origin**

#### Conceptos

- Una misma CloudFront distribution puede utilizar varios origins.
- **Cache behavior —** asocia un path pattern con un origin específico.
- **Estático —** `/images/*` puede dirigirse hacia Amazon S3.
- **Dinámico —** `/api/*` puede dirigirse hacia un ALB u otro origin HTTP.
- Los behaviors también controlan opciones como HTTPS, caching y acceso privado.

> **Nota —** **Price Class** decide qué grupos de edge locations puede utilizar la distribución. No es el mecanismo que selecciona entre varios origins.

**Docs —** Amazon CloudFront Developer Guide — Cache behavior settings

**Idea visual —** icono oficial de **Amazon CloudFront**. `example.com/images/*` apunta al icono oficial de **Amazon S3** y `example.com/api/*` apunta al icono oficial de **Application Load Balancer**.

### Slide 3 — Origin Group

**Título en slide —** ORIGIN GROUP — FAILOVER

#### Nombres en portal y examen

> **Origin group** — **primary origin** — **secondary origin** — **origin failover**

#### Conceptos

- **Origin group —** combina un origin primary y otro secondary.
- **Cache miss —** CloudFront consulta primero al primary.
- **Failover —** si el primary falla o devuelve un status code configurado, CloudFront prueba el secondary.
- **Métodos —** el failover aplica a solicitudes `GET`, `HEAD` y `OPTIONS`.

> **Nota —** Este es **origin failover de CloudFront**. No es el DNS failover de Route 53 estudiado en M8.

**Docs —** Amazon CloudFront Developer Guide — Optimize high availability with origin failover

**Idea visual —** icono oficial de **Amazon CloudFront** → `Primary Origin`. Una segunda flecha punteada llega al `Secondary Origin`. Cuando el primary devuelve error, la flecha activa cambia al secondary.

---

### Slide 4 — Geo-restriction y Field-level encryption

**Título en slide —** GEO-RESTRICTION — FIELD-LEVEL ENCRYPTION

#### Nombres en portal y examen

> **Geographic restriction** — **Field-level encryption**

#### Conceptos

- **Geo-restriction —** permite crear una allowlist o blocklist de países para la distribución.
- **Field-level encryption —** cifra campos específicos de datos sensibles en una solicitud.
- **Edge —** CloudFront cifra esos campos cerca del usuario antes de enviarlos al origin.
- **Clave pública —** CloudFront cifra con una public key; únicamente quien tiene la private key correspondiente puede descifrar.

> **Nota —** Field-level encryption no utiliza AWS KMS para cifrar esos campos. Utiliza criptografía asimétrica y una key pair.

**Docs —** Amazon CloudFront Developer Guide — Geographic restrictions  
**Docs —** Amazon CloudFront Developer Guide — Field-level encryption

**Idea visual —** icono oficial de **Amazon CloudFront**. A la izquierda, un mapa con países permitidos y bloqueados. A la derecha, un formulario donde únicamente el campo `card_number` queda cifrado antes de viajar al origin.

### Slide 5 — CloudFront Functions y Lambda@Edge

**Título en slide —** CLOUDFRONT FUNCTIONS — LAMBDA@EDGE

#### Nombres en portal y examen

> **CloudFront Functions** — **Lambda@Edge**

#### Conceptos

- **CloudFront Functions —** JavaScript ligero para eventos `viewer request` y `viewer response`.
- **Uso —** redirects, URL rewrites, headers y lógica breve de alta escala.
- **Restricciones —** no tiene network access ni acceso al request body.
- **Lambda@Edge —** Node.js o Python para lógica más compleja.
- **Más eventos —** también trabaja con `origin request` y `origin response`.
- **Más capacidades —** puede acceder a red, librerías y request body.

> **Nota —** CloudFront Functions está diseñado para ejecución submilisegundo. Lambda@Edge puede ejecutar funciones de hasta **30 segundos** según el evento y el límite aplicable.

**Docs —** Amazon CloudFront Developer Guide — Differences between CloudFront Functions and Lambda@Edge

**Idea visual —** icono oficial de **Amazon CloudFront** en el centro. Cerca del viewer, una caja `CloudFront Functions`. Cerca del origin, icono oficial de **AWS Lambda** etiquetado `Lambda@Edge`. Functions muestra `No network — No body`.

### Slide 6 — Origin Access Control

**Título en slide —** ORIGIN ACCESS CONTROL (OAC)

#### Nombres en portal y examen

> **Origin Access Control (OAC)** — **Origin Access Identity (OAI)**

#### Conceptos

- **OAC —** opción recomendada para que CloudFront acceda de forma autenticada a un bucket S3 privado.
- **Bucket policy —** permite acceso desde la distribución autorizada sin abrir el bucket al público.
- **OAI —** mecanismo legacy que todavía aparece en arquitecturas y preguntas antiguas.
- **OAC —** soporta escenarios modernos como SSE-KMS y requests dinámicos compatibles.

> **Nota —** OAC y OAI se utilizan con un **S3 bucket origin normal**. No funcionan con un bucket configurado como **S3 website endpoint**, porque ese endpoint se trata como custom origin.

**Docs —** Amazon CloudFront Developer Guide — Restrict access to an Amazon S3 origin

**Idea visual —** usuario → icono oficial de **Amazon CloudFront** → `OAC` → icono oficial de **Amazon S3** privado. Una flecha directa usuario → S3 aparece bloqueada. `OAI` aparece pequeño con etiqueta `Legacy`.

---

### Slide 7 — Signed URL y Signed Cookies

**Título en slide —** SIGNED URL — SIGNED COOKIES

#### Nombres en portal y examen

> **Signed URL** — **signed cookies**

#### Conceptos

- **Signed URL —** controla acceso temporal a un archivo o recurso concreto.
- **Signed cookies —** permiten acceder a varios archivos restringidos sin modificar cada URL.
- **Expiración —** CloudFront comprueba la firma y las condiciones antes de entregar el contenido.
- **Key groups —** AWS recomienda trusted key groups para validar las firmas.

> **Nota —** No confundas una **CloudFront signed URL** con una **S3 presigned URL** de M9. La primera controla contenido privado distribuido mediante CloudFront; la segunda autoriza temporalmente una operación directamente sobre Amazon S3.

**Docs —** Amazon CloudFront Developer Guide — Signed URLs and signed cookies

**Idea visual —** icono oficial de **Amazon CloudFront**. Un archivo tiene una `Signed URL` con reloj. Al lado, un navegador con `Signed Cookies` puede abrir varios objetos privados.

## Sesión 10.2 — Global Accelerator

### Slide 1 — AWS Global Accelerator

**Título en slide —** AWS GLOBAL ACCELERATOR

#### Nombres en portal y examen

> **AWS Global Accelerator** — **anycast** — **static IP**

#### Conceptos

- **Entrada fija —** un accelerator IPv4 recibe dos direcciones IPv4 estáticas anycast.
- **AWS global network —** el tráfico entra por un edge cercano y continúa por la red global de AWS.
- **TCP y UDP —** los listeners pueden aceptar ambos protocolos.
- **Endpoints —** puede dirigir tráfico hacia ALB, NLB, EC2 o Elastic IP.
- **Health —** envía nuevas conexiones hacia endpoints saludables.

> **Nota —** Global Accelerator **no cachea** HTML, imágenes ni otros objetos. Mejora la ruta de red hacia la aplicación.

**Docs —** AWS Global Accelerator Developer Guide — How AWS Global Accelerator works

**Idea visual —** icono oficial de **AWS Global Accelerator** como elemento principal. Dos IP estáticas anycast reciben usuarios globales y llevan el tráfico por la red de AWS hacia un ALB saludable.

---

### Slide 2 — Traffic Dial y Endpoint Weights

**Título en slide —** TRAFFIC DIAL — ENDPOINT WEIGHTS

#### Nombres en portal y examen

> **Traffic dial** — **endpoint weight** — **endpoint group**

#### Conceptos

- **Endpoint group —** agrupa endpoints de una AWS Region.
- **Traffic dial —** controla qué porcentaje del tráfico dirigido a ese endpoint group acepta esa Region.
- **Endpoint weight —** reparte tráfico entre endpoints dentro de un mismo endpoint group.
- **Blue-green —** permite mover gradualmente tráfico hacia un despliegue nuevo sin depender de cambios DNS.

> **Nota —** Esta capacidad es útil cuando los clientes almacenan DNS en caché y necesitas cambiar el reparto de tráfico rápidamente.

**Docs —** AWS Global Accelerator Developer Guide — Traffic dials and endpoint weights

**Idea visual —** icono oficial de **AWS Global Accelerator**. Un control `Traffic Dial 20 %` mueve una parte del tráfico hacia el ambiente `Green`; el resto continúa hacia `Blue`.

---

### Slide 3 — Desempate

**Título en slide —** CACHÉ O IP FIJA

#### Conceptos

| El enunciado pide | El servicio |
|---|---|
| HTML, imágenes, video HTTP, URL firmada | CloudFront |
| IP que no cambia, TCP o UDP, sin caché | Global Accelerator |
| Un nombre que elige región | Route 53, ya visto en el curso, no estos dos |

> **Nota —** CloudFront y Global Accelerator utilizan la red global de AWS, pero resuelven problemas diferentes. CloudFront distribuye contenido HTTP mediante caché; Global Accelerator optimiza el camino de red hacia endpoints regionales.

**Idea visual —** conservar la tabla como elemento principal. Icono oficial de **Amazon CloudFront** junto a la primera fila e icono oficial de **AWS Global Accelerator** junto a la segunda. Amazon Route 53 aparece únicamente como referencia de M8.

## Sesión 10.3 — Arquitectura, sitio con borde

### Slide 1 — CloudFront delante del sitio

**Título en slide —** ARQUITECTURA — CLOUDFRONT DELANTE DEL SITIO

#### Conceptos

- El usuario accede únicamente a Amazon CloudFront.
- Los archivos estáticos se obtienen desde un bucket Amazon S3 privado.
- OAC permite que CloudFront lea el bucket sin hacerlo público.
- Un segundo cache behavior puede enviar contenido dinámico hacia el ALB.

> **Nota —** En M9 vimos el S3 website endpoint público. En esta arquitectura el patrón cambia — para mantener el bucket privado con OAC, CloudFront utiliza el **S3 bucket origin normal**, no el website endpoint.

**Idea visual —**

5. `Cache behavior — /api/*` → icono oficial de **Application Load Balancer**.
6. Certificado HTTPS etiquetado `M17`.
7. **AWS Global Accelerator** no aparece en esta arquitectura.
