## Sesión 4.1 — La instancia

### Slide 1 — Amazon EC2

**Título en slide —** AMAZON EC2

#### Nombres en portal y examen

> **Amazon Elastic Compute Cloud (Amazon EC2)** — **EC2 instance**

#### Conceptos

- **Amazon EC2 —** capacidad de cómputo virtual bajo demanda.
- **Instancia —** máquina virtual con CPU, memoria, networking y un sistema operativo que administras.
- **Ubicación —** una instancia se ejecuta dentro de una Availability Zone.
- **AMI —** define la imagen desde la que arranca. Se estudia en M5.
- **Permisos —** si la instancia llama a otro servicio AWS, utiliza un IAM role de M3.

> **Nota —** Amazon EC2 es IaaS. AWS administra el hardware y la virtualización; tú administras el guest OS y las aplicaciones de la instancia.

**Docs —**  
[Amazon EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/concepts.html)

### Slide 2 — Arranque, hibernación y acceso

**Título en slide —** USER DATA, HIBERNATE Y ACCESO

#### Nombres en portal y examen

> **User data** — **Hibernate** — **EC2 Instance Connect**

#### Conceptos

- **User data —** permite ejecutar instrucciones al lanzar una instancia. En Linux, por defecto se ejecuta durante el primer arranque y como `root`.
- **Hibernate —** guarda el contenido de la RAM en el volumen raíz EBS y permite reanudar procesos después.
- **Stop —** conserva los volúmenes EBS, pero no conserva el contenido de la RAM como Hibernate.
- **EC2 Instance Connect —** coloca temporalmente una llave pública SSH en la instancia para iniciar la conexión.

> **Nota —** Para Hibernate, el volumen raíz EBS debe cumplir los requisitos de hibernación y estar cifrado. EC2 Instance Connect mantiene la llave pública temporal durante aproximadamente **60 segundos**.

**Docs —**  
[EC2 user data](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/user-data.html)  
[Hibernate your EC2 instance](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Hibernate.html)  
[EC2 Instance Connect](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connect-linux-inst-eic.html)

**Idea visual —** icono oficial de **Amazon EC2** en el centro. A su alrededor, tres elementos — script `User data`, RAM → EBS para `Hibernate` y una llave temporal para `EC2 Instance Connect`.

## Sesión 4.2 — Qué tamaño pedir

### Slide 1 — La familia es el trabajo

**Título en slide —** FAMILIA SEGÚN EL WORKLOAD

#### Nombres en portal y examen

> **Burstable performance** — **General purpose** — **Compute optimized** — **Memory optimized** — **Storage optimized** — **Accelerated computing**

#### Conceptos

- **T —** CPU con baseline y capacidad de burst para cargas variables.
- **M —** equilibrio entre CPU y memoria.
- **C —** cargas intensivas en CPU.
- **R —** cargas intensivas en memoria.
- **I / D —** workloads que necesitan alto rendimiento de almacenamiento local.
- **P / G —** accelerated computing, especialmente cargas con GPU.

> **Nota —** No elijas la familia por una letra memorizada. Busca primero el cuello de botella del escenario — CPU, memoria, almacenamiento o aceleración.

### Slide 2 — Placement Groups

**Título en slide —** PLACEMENT GROUPS

#### Nombres en portal y examen

> **Cluster placement group** — **Partition placement group** — **Spread placement group** — **Elastic Fabric Adapter (EFA)**

#### Conceptos

- **Cluster —** coloca instancias cerca dentro de una sola AZ para baja latencia y alto throughput.
- **Partition —** separa grupos de instancias en particiones que no comparten hardware subyacente.
- **Spread —** coloca un grupo pequeño de instancias críticas sobre hardware distinto.
- **EFA —** interfaz de red para workloads HPC que necesitan comunicación de alto rendimiento.

> **Nota —** Un Spread placement group admite hasta **7 instancias en ejecución por AZ**. Partition admite hasta **7 particiones por AZ**. Para HPC con comunicación estrecha entre nodos, piensa primero en **Cluster**.

**Docs —**  
[Placement groups](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/placement-groups.html)  
[Placement strategies](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/placement-strategies.html)

### Slide 3 — Launch Template

**Título en slide —** LAUNCH TEMPLATE

#### Nombres en portal y examen

> **Launch template** — **launch configuration**

#### Conceptos

- **Launch template —** guarda parámetros reutilizables para lanzar EC2, como AMI, instance type, key pair, security groups y user data.

- **Mixed instances —** para combinar varios instance types y capacidad On-Demand + Spot en un Auto Scaling group se utiliza una launch template.
- **Launch configuration —** mecanismo legacy que AWS recomienda migrar a launch templates.

> **Nota —** Las cuentas creadas desde el **1 de octubre de 2024** ya no pueden crear nuevas launch configurations por ningún método. Auto Scaling se estudia en profundidad en M6; aquí solo necesitas reconocer la diferencia para el examen.

## Sesión 4.3 — Cómo se paga

### Slide 1 — On-Demand

**Título en slide —** ON-DEMAND

#### Nombres en portal y examen

> **On-Demand Instances**

#### Conceptos

- Pagas capacidad EC2 según el uso, sin compromiso de 1 o 3 años.
- Encaja cuando el workload es nuevo, impredecible o no quieres comprometer consumo futuro.
- No requiere pago inicial ni reserva de largo plazo.

> **Nota —** On-Demand es la referencia base frente a la que AWS compara los descuentos de otras opciones de compra.

**Docs —**  
[EC2 billing and purchasing options](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instance-purchasing-options.html)

**Idea visual —** icono oficial de **Amazon EC2** junto a un ticket `On-Demand` sin contrato ni fecha de compromiso.

### Slide 2 — Reserved Instances

**Título en slide —** RESERVED INSTANCES

#### Nombres en portal y examen

> **Reserved Instances (RI)** — **Standard RI** — **Convertible RI**

#### Conceptos

- **Reserved Instance —** descuento de facturación por comprometer una configuración durante 1 o 3 años.
- **Standard —** mayor descuento, pero no puede intercambiarse por otra configuración.
- **Convertible —** menor descuento, pero puede intercambiarse por otra Convertible RI con atributos diferentes.
- **No es una máquina —** la RI no representa el ID de una instancia concreta.

> **Nota —** Una **Regional RI** entrega descuento pero no reserva capacidad. Una **Zonal RI** también reserva capacidad en la Availability Zone seleccionada.

**Docs —**  
[Reserved Instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-reserved-instances.html)  
[Regional and zonal Reserved Instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/reserved-instances-scope.html)

**Idea visual —** icono oficial de **Amazon EC2** junto a un contrato `1 o 3 años`. Debajo, dos caminos — `Regional = descuento` y `Zonal = descuento + capacidad`.

### Slide 3 — Savings Plans

**Título en slide —** SAVINGS PLANS

#### Nombres en portal y examen

> **Compute Savings Plans** — **EC2 Instance Savings Plans**

#### Conceptos

- **Savings Plans —** compromiso de gasto medido en USD por hora durante 1 o 3 años.
- **Compute Savings Plans —** mayor flexibilidad entre EC2, AWS Fargate y AWS Lambda.
- **EC2 Instance Savings Plans —** se comprometen con una familia de instancias en una Region.
- **Capacidad —** Savings Plans reducen precio, pero no reservan capacidad.

> **Nota —** Reserved Instances comprometen una configuración EC2. Savings Plans comprometen **gasto por hora**. Esa diferencia aparece con frecuencia en preguntas de coste.

**Docs —**

### Slide 4 — Spot

**Título en slide —** SPOT INSTANCES

#### Nombres en portal y examen

> **Spot Instances** — **Spot Fleet**

#### Conceptos

- **Spot —** utiliza capacidad EC2 disponible a menor precio que On-Demand.
- **Interrupción —** AWS puede recuperar esa capacidad cuando la necesita.
- **Uso ideal —** batch, procesamiento distribuido o workloads que toleran interrupciones.
- **No ideal —** una única instancia que contiene estado crítico o que no puede detenerse.

> **Nota —** AWS proporciona un aviso de interrupción de aproximadamente **2 minutos** para determinados comportamientos de interrupción. Spot Fleet continúa apareciendo en documentación y preguntas antiguas, pero AWS actualmente recomienda **EC2 Fleet o Auto Scaling groups** para diseños nuevos.

**Docs —**  
[Spot Instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-spot-instances.html)

### Slide 5 — Dedicated

**Título en slide —** DEDICATED HOST Y DEDICATED INSTANCE

#### Nombres en portal y examen

> **Dedicated Host** — **Dedicated Instance**

#### Conceptos

- **Dedicated Host —** servidor físico completo dedicado a tu uso, con visibilidad y control sobre el host.
- **BYOL —** encaja cuando licencias existentes dependen de sockets, cores o VMs.
- **Dedicated Instance —** ejecuta la instancia sobre hardware dedicado a una sola cuenta, pero sin elegir ni controlar el host.

> **Nota —** Si necesitas controlar el servidor físico o aplicar licencias ligadas al hardware, piensa en **Dedicated Host**. Si solo necesitas aislamiento de hardware entre cuentas, piensa en **Dedicated Instance**.

**Docs —**

### Slide 6 — Capacity Reservation

**Título en slide —** ON-DEMAND CAPACITY RESERVATION

#### Nombres en portal y examen

> **On-Demand Capacity Reservation** — **Capacity Reservation**

#### Conceptos

- Reserva capacidad EC2 para una configuración concreta dentro de una Availability Zone.
- No requiere el compromiso de precio de una Reserved Instance.
- Por sí sola, no entrega descuento sobre la tarifa On-Demand.
- La capacidad reservada genera cargo aunque permanezca sin utilizar.

> **Nota —** Capacity Reservation resuelve **disponibilidad de capacidad**, no reducción de precio. Un Savings Plan o una Regional RI compatible puede aplicar su descuento al uso de esa capacidad.

**Docs —**

## Sesión 4.4 — Security group

### Slide 1 — El firewall de la instancia

**Título en slide —** SECURITY GROUP

#### Nombres en portal y examen

> **Security group**

#### Conceptos

- **Alcance —** controla tráfico hacia y desde recursos asociados, como la interfaz de red de una EC2.
- **Solo Allow —** las reglas permiten tráfico; no escribes reglas `Deny`.
- **Stateful —** la respuesta a tráfico permitido puede regresar sin crear la regla inversa.
- **Origen —** puede ser una IP, un CIDR u otro security group.
- **Security group reference —** permite autorizar recursos según el security group al que están asociados.

> **Nota —** El Network ACL opera a nivel de subnet, es stateless y permite `Allow` y `Deny`. Se estudia en M19.

**Docs —**  
[EC2 security groups](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-security-groups.html)  
[Security group rules](https://docs.aws.amazon.com/vpc/latest/userguide/security-group-rules.html)

**Idea visual —** icono oficial de **Security Group** disponible en draw.io rodeando una instancia **Amazon EC2**. Una flecha `443` entra y su respuesta sale automáticamente. Fuera del security group aparece la subnet con la etiqueta `NACL — M19`.

Cada vez que hay que detener la instancia y volver a iniciarla, la aplicación tarda unos 3 minutos en arrancar, porque antes deben ejecutarse varios programas de software auxiliares para que pueda funcionar. El grupo quiere reducir al mínimo ese tiempo de arranque siempre que haya que detener el sistema y ponerlo en marcha después.

Como arquitecto de soluciones, ¿qué solución recomendarías para este caso de uso?

A) Utilizar Instancia EC2 Hibernate

B) Utilizar datos de usuario de EC2

C) Utilizar metadatos de EC2

D) Crea una AMI y, a partir de ella, lanza las instancias EC2

✅ **Respuesta —** A

Cuando la instancia vuelve a iniciarse, el sistema restaura ese estado en memoria, incluidos los procesos que estaban ejecutándose. Esto evita repetir un arranque completo de la aplicación y reduce el tiempo necesario para volver al estado operativo anterior.

3. A developer has allowed inbound traffic on the relevant ports both in the Security Group of an Amazon EC2 instance and in the Network Access Control List (Network ACL) of the subnet that contains that instance. The developer still cannot connect to the service running on the Amazon EC2 instance.

As a solutions architect, how would you correct this issue?

A) Because Network ACLs are stateful, allowing inbound traffic on the necessary ports is enough to enable the connection. Because Security Groups are stateless, both inbound and outbound traffic must be allowed

B) The IAM Role defined in the Security Group differs from the IAM Role that is granted access in the Network ACLs

C) Because Security Groups are stateful, allowing inbound traffic on the necessary ports is enough to enable the connection. Because Network ACLs are stateless, both inbound and outbound traffic must be allowed

D) Network ACL rules should never be changed from the command line. Trying to change a rule from the command line blocks the rule and produces erratic behavior

✅ **Respuesta —** C

💡 **Explanation —** Security Groups are **stateful**, so return traffic for an allowed inbound connection is automatically permitted regardless of outbound rules. Network ACLs are **stateless**, so the appropriate traffic must be explicitly allowed in both directions. If the inbound rule exists but the corresponding outbound traffic is blocked by the Network ACL, the connection will fail.
