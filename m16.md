## Sesión 16.1 — Amazon CloudWatch

### Slide 1 — Amazon CloudWatch

**Título en slide**

AMAZON CLOUDWATCH

#### Nombres en portal y examen

> **Amazon CloudWatch**  
> **Metrics** / **Métricas**  
> **Logs** / **Registros**  
> **Alarms** / **Alarmas**

#### Conceptos

- **Amazon CloudWatch** centraliza métricas, logs y alarmas para observar el estado y rendimiento de recursos y aplicaciones.
- Las métricas representan valores numéricos en el tiempo, mientras CloudWatch Logs almacena eventos y mensajes generados por aplicaciones y servicios.
- Las alarmas evalúan métricas y pueden enviar notificaciones o iniciar determinadas acciones cuando cambia su estado.
- CloudWatch observa operación y rendimiento, pero no sustituye CloudTrail para auditoría ni AWS Config para historial de configuración.

> **Idea visual**  
> Métrica + log → Amazon CloudWatch → gráfico, búsqueda y alarma.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 2 — Métricas de CloudWatch

**Título en slide**

MÉTRICAS

#### Nombres en portal y examen

> **Metric** / **Métrica**  
> **Basic monitoring** / **Monitorización básica**  
> **Detailed monitoring** / **Monitorización detallada**

#### Conceptos

- Una métrica representa un valor numérico como CPU, latencia, errores o profundidad de una cola medido durante diferentes periodos.
- Amazon EC2 publica la mayoría de métricas básicas cada **5 minutos**, mientras detailed monitoring permite periodos de **1 minuto**.
- Detailed monitoring tiene costo adicional y resulta útil cuando necesitas detectar cambios con mayor rapidez.
- Las métricas personalizadas permiten publicar valores propios de una aplicación cuando los datos predeterminados no son suficientes.

> **Nota numérica**  
> Los status checks de EC2 se publican cada **1 minuto incluso con basic monitoring**.  
> CloudWatch conserva las métricas durante **15 meses**.

> **Idea visual**  
> CPU con puntos cada 5 minutos frente a puntos cada 1 minuto.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 3 — Métricas de facturación

**Título en slide**

MÉTRICAS DE FACTURACIÓN

#### Nombres en portal y examen

> **EstimatedCharges**  
> **AWS/Billing**

#### Conceptos

- CloudWatch puede recibir métricas con el costo estimado de la cuenta cuando habilitas las alertas de facturación.
- La métrica `EstimatedCharges` representa cargos mundiales aunque los recursos se encuentren distribuidos entre varias regiones.
- Los datos de facturación se almacenan únicamente en **US East (N. Virginia), `us-east-1`**.
- Una alarma de facturación compara el gasto actual contra un umbral y no realiza una proyección del gasto futuro.

> **Trampa de examen**  
> Si preguntan dónde crear una CloudWatch billing alarm, la región es **`us-east-1`**.

> **Idea visual**  
> Regiones globales → `AWS/Billing` → `us-east-1` → alarma.

### Slide 4 — CloudWatch Agent

**Título en slide**

CLOUDWATCH AGENT

#### Nombres en portal y examen

> **CloudWatch Agent**  
> **Custom metric** / **Métrica personalizada**

#### Conceptos

- Las métricas estándar de EC2 incluyen información como CPU y red, pero no proporcionan directamente uso de RAM o porcentaje de disco del sistema operativo.
- **CloudWatch Agent** recopila métricas adicionales desde Linux, Windows, EC2 y determinados servidores externos.
- El agente también puede enviar archivos de log del sistema operativo y de aplicaciones hacia CloudWatch Logs.
- Si el escenario pide memoria, swap o utilización del filesystem en EC2, necesitas el agente u otro mecanismo de métricas personalizadas.

> **Idea visual**  
> EC2 sin agente → CPU y Network. EC2 con agente → RAM, swap y disk.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 5 — CloudWatch Logs

**Título en slide**

CLOUDWATCH LOGS

#### Nombres en portal y examen

> **CloudWatch Logs**  
> **Log group** / **Grupo de logs**  
> **Log stream** / **Flujo de logs**

#### Conceptos

- CloudWatch Logs centraliza mensajes generados por aplicaciones y servicios para búsqueda, diagnóstico y retención.
- Un **log group** agrupa logs relacionados y cada **log stream** representa una secuencia de eventos procedente de una fuente.
- La retención puede configurarse para eliminar automáticamente eventos antiguos o conservarlos sin fecha de expiración.
- Los logs de una aplicación explican qué ocurrió dentro del workload, pero no quién realizó una llamada administrativa a AWS.

> **Idea visual**  
> Aplicaciones → log streams → log group → búsqueda.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 6 — Metric filter

**Título en slide**

METRIC FILTER

#### Nombres en portal y examen

> **Metric filter** / **Filtro de métrica**

#### Conceptos

- Un metric filter examina eventos dentro de un log group y busca patrones como `ERROR`, `AccessDenied` o códigos específicos.
- Cada coincidencia puede convertirse en una métrica personalizada que después se grafica o utiliza en una alarma.
- CloudTrail puede entregar eventos a CloudWatch Logs para detectar patrones de llamadas API mediante metric filters.
- El patrón habitual es **logs → metric filter → métrica → CloudWatch alarm → Amazon SNS**.

> **Idea visual**  
> Logs → filtro `ERROR` → `ErrorCount` → alarma.

---

### Slide 7 — Subscription filter

**Título en slide**

SUBSCRIPTION FILTER

#### Nombres en portal y examen

> **Subscription filter** / **Filtro de suscripción**

#### Conceptos

- Un subscription filter envía eventos de CloudWatch Logs hacia otro servicio para procesarlos de forma continua.
- Puede entregar logs a destinos como AWS Lambda, Kinesis Data Streams o Amazon Data Firehose.
- Se utiliza cuando otra aplicación necesita consumir o transformar los eventos conforme llegan.
- Un metric filter convierte coincidencias en números, mientras un subscription filter reenvía los eventos originales.

> **Idea visual**  
> Log group → subscription filter → Lambda o stream.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 8 — CloudWatch Alarms

**Título en slide**

CLOUDWATCH ALARMS

#### Nombres en portal y examen

> **CloudWatch alarm** / **Alarma de CloudWatch**  
> **OK**  
> **ALARM**  
> **INSUFFICIENT_DATA**

#### Conceptos

- Una alarma evalúa una métrica contra las condiciones configuradas y cambia entre `OK`, `ALARM` e `INSUFFICIENT_DATA`.
- Puede enviar una notificación mediante Amazon SNS o activar determinadas automatizaciones y acciones sobre EC2.
- Un caso típico de examen es **CPU superior a un umbral → CloudWatch Alarm → SNS → correo al equipo**.
- No necesitas una función Lambda intermedia cuando SNS puede entregar directamente la notificación requerida.

> **Ejemplo**  
> `CPUUtilization > 80 %` → `ALARM` → Amazon SNS.

> **Logo** `recursos/aws/security/cloudwatch.svg`

### Slide 9 — Recuperación de EC2

**Título en slide**

RECUPERACIÓN DE EC2

#### Nombres en portal y examen

> **Recover action** / **Acción de recuperación**  
> `StatusCheckFailed_System`

#### Conceptos

- Una CloudWatch alarm puede recuperar automáticamente una instancia cuando falla el **system status check** por un problema de infraestructura subyacente.
- La acción utiliza `StatusCheckFailed_System` y migra la instancia compatible hacia hardware saludable.
- La instancia recuperada conserva su instance ID, IP privada, Elastic IP y demás metadata, pero pierde los datos que estaban únicamente en RAM.
- Para el patrón del SAA-C03, la instancia debe utilizar **Amazon EBS como root volume** y una instancia terminada no puede recuperarse.

> **Caso Check yourself EN**  
> Recuperación automática de una única instancia con máximo **10 minutos de downtime**, id 38.

> **Idea visual**  
> EC2 con fallo físico → CloudWatch alarm → nuevo host → misma instancia lógica.

## Sesión 16.2 — Auditoría y detección

### Slide 1 — AWS CloudTrail

**Título en slide**

AWS CLOUDTRAIL

#### Nombres en portal y examen

> **AWS CloudTrail**  
> **Management event** / **Evento de administración**  
> **Data event** / **Evento de datos**

#### Conceptos

- **AWS CloudTrail** registra actividad de API para saber quién realizó una acción, cuándo ocurrió, desde dónde y qué operación utilizó.
- Los management events incluyen acciones administrativas como crear recursos, modificar configuraciones o cambiar políticas.
- Los data events registran operaciones de alto volumen sobre recursos específicos y necesitan configuración adicional.
- CloudTrail se utiliza para auditoría y análisis forense, no para medir CPU o rendimiento de una aplicación.

> **Ejemplo**  
> Investigar quién ejecutó `PutBucketPolicy` sobre un bucket Amazon S3.

> **Logo** `recursos/aws/security/cloudtrail.svg`

---

### Slide 2 — CloudTrail Event History

**Título en slide**

CLOUDTRAIL EVENT HISTORY

#### Conceptos

- **Event History** está habilitado de forma predeterminada y permite consultar los últimos **90 días** de management events.
- El historial corresponde a una cuenta y una región y no incluye data events, Insights events ni network activity events.
- Para conservar actividad durante más tiempo necesitas crear un trail o un CloudTrail Lake event data store.
- Un trail puede entregar los archivos a Amazon S3 y opcionalmente integrarse con CloudWatch Logs.

> **Nota de examen**  
> **90 días** es el dato clave de Event History.

> **Idea visual**  
> API calls → Event History `90 días` → trail → S3 para largo plazo.

### Slide 3 — Trail multirregión y organización

**Título en slide**

CLOUDTRAIL Y ALCANCE

#### Nombres en portal y examen

> **Multi-Region trail** / **Trail multirregión**  
> **Organization trail** / **Trail de organización**

#### Conceptos

- Un multi-Region trail registra actividad en todas las regiones habilitadas y evita dejar regiones sin cobertura de auditoría.
- AWS recomienda registrar actividad en todas las regiones para mejorar la visibilidad y seguridad de la cuenta.
- Un organization trail permite recopilar actividad de las cuentas pertenecientes a AWS Organizations.
- El Event History de la cuenta de administración no agrega automáticamente los eventos de todas las cuentas miembro.

> **Idea visual**  
> Varias regiones y varias cuentas → organization trail → bucket central.

### Slide 4 — Amazon GuardDuty

**Título en slide**

AMAZON GUARDDUTY

#### Nombres en portal y examen

> **Amazon GuardDuty**  
> **Threat detection** / **Detección de amenazas**  
> **Finding** / **Hallazgo**

#### Conceptos

- **Amazon GuardDuty** supervisa continuamente actividad para detectar comportamientos maliciosos, anómalos o no autorizados.
- Sus fuentes fundamentales incluyen **CloudTrail management events, VPC Flow Logs y DNS logs**.
- Utiliza threat intelligence y Machine Learning para detectar situaciones como credenciales comprometidas o comunicación con IP maliciosas.
- GuardDuty genera findings de seguridad y no requiere que crees manualmente VPC Flow Logs o Route 53 DNS query logging para sus fuentes fundamentales.

> **Nota numérica**  
> Al habilitar GuardDuty por primera vez en una región existe actualmente una prueba gratuita de **30 días** para detección de amenazas.

> **Caso Check yourself ES**  
> Identificar las fuentes fundamentales que analiza GuardDuty, id 21.

> **Logo** `recursos/aws/security/guardduty.svg`

> **Idea visual**  
> CloudTrail + VPC Flow Logs + DNS → GuardDuty → security finding.

AWS CONFIG

> **AWS Config**  
> **Configuration history** / **Historial de configuración**

#### Conceptos

### Slide 2 — Certificados próximos a vencer

**Título en slide**

CONFIG Y CERTIFICADOS ACM

#### Nombres en portal y examen

> `ACM_CERTIFICATE_EXPIRATION_CHECK`  
> `daysToExpiration`

#### Conceptos

- La regla administrada `ACM_CERTIFICATE_EXPIRATION_CHECK` detecta certificados ACM próximos a caducar.

### Slide 1 — Trail, Config y CloudWatch

TRAIL, CONFIG Y CLOUDWATCH

| Pregunta | Herramienta |
|---|---|
| ¿**Quién** llamó a la API y con qué parámetros? | **CloudTrail** |

## Sesión 16.8 — Arquitecturas

### Slide 1 — Monitoreo y auditoría

**Título en slide**

MONITOREO Y AUDITORÍA

#### Conceptos

- Las instancias del Auto Scaling Group publican métricas y una CloudWatch alarm puede notificar al equipo cuando se supera un umbral.
- Amazon SNS entrega la notificación sin necesitar una función intermedia cuando el requisito es únicamente enviar un correo.
- CloudTrail registra en paralelo las llamadas administrativas y puede entregar los eventos hacia Amazon S3 para retención.
- CloudWatch está en el plano de observabilidad y CloudTrail en el de auditoría, por lo que ninguno forma parte del camino HTTP del usuario.

> **Idea visual**
>
> 1. Fondo **líneas punteadas** AZ A | AZ B.
> 2. Usuario → ALB → instancias EC2.
> 3. EC2 → métrica → CloudWatch Alarm → Amazon SNS.
> 4. CloudTrail → Amazon S3 fuera del flujo de usuario.

---

### Slide 2 — Alerta sobre llamadas API

**Título en slide**

ALERTA SOBRE API

#### Conceptos

- CloudTrail registra las llamadas API y puede entregar esos eventos a CloudWatch Logs.
- Un metric filter identifica los códigos o patrones de error que deben convertirse en una métrica.
- Una CloudWatch alarm evalúa la tasa de esa métrica y Amazon SNS notifica al equipo correspondiente.
- Este patrón permite alertas casi en tiempo real sin ejecutar consultas periódicas sobre archivos históricos.

> **Flujo**  
> CloudTrail → CloudWatch Logs → metric filter → CloudWatch Alarm → Amazon SNS.

> **Caso Check yourself EN**  
> Gran cantidad de llamadas API ilegales que necesitan alertas automáticas, id 61.

## Check yourself

> **5 ES** + **5 EN**. Las preguntas EN se mantienen sin traducir. Solo se evalúa contenido enseñado en este módulo.

### Banco español

Una empresa ha pasado de ser una startup pequeña a una organización que emplea a más de 1000 personas. A medida que el equipo ha crecido, la empresa ha observado hace poco un comportamiento extraño: la configuración de los buckets S3 cambia con regularidad.

¿Qué me recomiendas?

A) De los certificados creados mediante ACM, supervisa la métrica de CloudWatch days to expiry. B) De los certificados importados en ACM, supervisa la métrica de CloudWatch days to expiry. Para monitorizar dichos certificados en función de la métrica days to expiry (días hasta caducidad), crea una alarma de CloudWatch y, a continuación, activa una acción personalizada de notificación al equipo de seguridad
