## Sesión 14.3 — Ingesta

### Slide 1 — Amazon Kinesis Data Streams

**Título en slide**

AMAZON KINESIS DATA STREAMS

#### Nombres en portal y examen

> **Amazon Kinesis Data Streams** — stream — shard — partition key

#### Conceptos

- **Amazon Kinesis Data Streams** recibe y conserva temporalmente eventos para que una o varias aplicaciones los procesen en tiempo real.
- Los registros mantienen el orden dentro de cada shard.
- La **partition key** determina cómo se distribuyen los registros entre los shards.
- Varios consumidores pueden leer el mismo flujo de forma independiente.
- La retención predeterminada es de 24 horas y puede ampliarse hasta 365 días.

> **Nota**  
> Kinesis Data Streams no es el archivo final de los datos. Conserva temporalmente el flujo para que uno o más consumidores puedan procesarlo.

> **Logo** `recursos/aws/analytics/kinesis.svg`

> **Idea visual**  
> Icono oficial de **Amazon Kinesis Data Streams**. Varios productores escriben eventos sobre tres shards y dos consumidores leen el mismo stream.

### Slide 2 — Capacidad de Kinesis Data Streams

**Título en slide**

ON-DEMAND — SHARDS — ENHANCED FAN-OUT

#### Conceptos

- En **on-demand mode**, Kinesis administra automáticamente la capacidad del stream sin que tengas que dimensionar shards.
- En **provisioned mode**, defines el número de shards según el throughput que necesita la aplicación.
- Un `ProvisionedThroughputExceededException` puede indicar que falta capacidad o que las partition keys están distribuyendo mal el tráfico.
- **Enhanced fan-out** entrega a cada consumidor registrado hasta 2 MB por segundo de throughput dedicado por shard.

> **Nota**  
> Si aparece throttling, revisa primero la distribución de las partition keys y la capacidad del stream. Los retries deben utilizar backoff.

> **Logo** `recursos/aws/analytics/kinesis.svg`

> **Idea visual**  
> Icono oficial de **Amazon Kinesis Data Streams**. A la izquierda, un stream on-demand escala sin mostrar shards administrados manualmente. A la derecha, varios consumidores utilizan Enhanced Fan-Out con una vía dedicada por consumidor.

### Slide 1 — AWS Glue

**Título en slide**

AWS GLUE

#### Nombres en portal y examen

> **AWS Glue** — **Data Catalog** — crawler — ETL

#### Conceptos

- **AWS Glue** permite descubrir, preparar y transformar datos sin administrar la infraestructura del proceso.
- Un **crawler** inspecciona datasets y registra su esquema dentro del AWS Glue Data Catalog.
- El **Data Catalog** guarda metadatos sobre tablas y esquemas, pero no mueve los archivos originales.
- Los Glue jobs pueden ejecutar procesos ETL para limpiar o transformar datos.

> **Nota**  
> Si Glue cataloga archivos almacenados en S3, los objetos continúan viviendo en S3.

### Slide 3 — Amazon Athena

**Título en slide**

AMAZON ATHENA

#### Nombres en portal y examen

> **Amazon Athena**

#### Conceptos

- **Amazon Athena** ejecuta SQL directamente sobre datos almacenados en Amazon S3.
- No necesitas aprovisionar ni mantener un cluster para realizar las consultas.
- Athena puede utilizar AWS Glue Data Catalog para conocer las tablas y sus esquemas.
- Formatos columnares como Parquet u ORC y una buena estrategia de particiones reducen los bytes que la consulta necesita escanear.
- Reducir los datos escaneados mejora el rendimiento y normalmente también disminuye el coste.

> **Nota**  
> Si el escenario pide consultas SQL ad hoc sobre archivos en S3 con el menor trabajo operativo posible, piensa primero en Athena.

5. A gaming company is developing a mobile game that streams score updates to a backend processor and then publishes the results on a leaderboard. The company has hired you as an AWS Certified Solutions Architect Associate. The company also wants to minimize the management overhead required to maintain the solution.

Which of the following will you recommend to meet these requirements?

A) Push score updates to Amazon Kinesis Data Streams, which uses a fleet of Amazon EC2 instances (with Auto Scaling) to process the updates in Amazon Kinesis Data Streams and then store these processed updates in Amazon DynamoDB

B) Push score updates to Amazon Kinesis Data Streams, which uses an AWS Lambda function to process these updates and then store these processed updates in Amazon DynamoDB

C) Push score updates to an Amazon Simple Queue Service (Amazon SQS) queue that uses a fleet of Amazon EC2 instances (with Auto Scaling) to process these updates in the Amazon SQS queue and then store these processed updates in an Amazon RDS MySQL database
