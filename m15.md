### Slide 2 — Amazon Rekognition

**Título en slide**

AMAZON REKOGNITION

#### Nombres en portal y examen

> **Amazon Rekognition**

#### Conceptos

- **Amazon Rekognition** analiza imágenes y video para identificar objetos, escenas, personas y otros elementos visuales.
- Puede detectar texto visible dentro de una imagen o video.
- También permite analizar rostros y detectar contenido inapropiado.
- No está diseñado para extraer la estructura de formularios, tablas o facturas.

> **Nota**  
> Si el problema es entender lo que aparece visualmente en una imagen o video, piensa en Rekognition. Si necesitas extraer campos estructurados de un documento, piensa en Textract.

> **Logo** `recursos/aws/ai-ml/rekognition.svg`

> **Idea visual**  
> Icono oficial de **Amazon Rekognition** frente a una fotografía. Sobre la imagen aparecen etiquetas como `Person`, `Car`, `Text` y `Moderation`.

### Slide 3 — Amazon Textract

**Título en slide**

AMAZON TEXTRACT

#### Nombres en portal y examen

> **Amazon Textract**

#### Conceptos

- **Amazon Textract** extrae texto escrito o impreso desde documentos.
- Puede reconocer formularios mediante pares key-value y detectar tablas y sus celdas.
- También dispone de capacidades específicas para documentos como facturas, recibos e identificaciones.
- Conserva información sobre la estructura del documento que un OCR básico no proporciona.

> **Nota**  
> Para una factura, formulario o tabla dentro de un PDF, piensa en **Textract**, no en Rekognition.

> **Logo** `recursos/aws/otros/textract.svg`

> **Idea visual**

### Slide 7 — Amazon Lex

**Título en slide**

AMAZON LEX

#### Nombres en portal y examen

> **Amazon Lex** — **intent** — **slot**

#### Conceptos

- **Amazon Lex** permite crear interfaces conversacionales mediante texto o voz.
- Un **intent** representa lo que el usuario quiere conseguir.
- Los **slots** recopilan los datos necesarios para completar esa intención.
- El servicio puede integrarse con otros componentes de la aplicación para ejecutar la acción solicitada.

> **Nota**  
> Lex es el motor conversacional. No necesitas estudiar un contact center completo para reconocerlo en el examen.

### Slide 8 — Amazon Comprehend

**Título en slide**

AMAZON COMPREHEND

#### Nombres en portal y examen

> **Amazon Comprehend** — **sentiment** — **entities**

#### Conceptos

- **Amazon Comprehend** utiliza procesamiento de lenguaje natural para analizar texto.
- Puede detectar entidades como personas, organizaciones o lugares.
- Puede identificar el sentimiento del texto como positivo, negativo, neutral o mixto.
- También puede detectar características como idioma, frases clave y otros elementos lingüísticos.

> **Nota**  
> Si Textract primero extrae el texto de un documento, Comprehend puede analizar después lo que ese texto significa.

> **Logo** `recursos/aws/ai-ml/comprehend.svg`

### Slide 9 — Custom Entity Recognition

**Título en slide**

COMPREHEND CUSTOM ENTITY RECOGNITION

#### Conceptos

- **Custom Entity Recognition** permite enseñar a Amazon Comprehend entidades específicas de tu negocio que no existen entre las categorías genéricas.
- Puedes utilizarlo para reconocer elementos como códigos internos, nombres de productos o ingredientes.
- El servicio administra gran parte del proceso de entrenamiento y despliegue del recognizer.
- Necesitas proporcionar datos de entrenamiento o documentos anotados para definir las entidades que quieres reconocer.

> **Nota**  
> Esto no convierte a Comprehend en SageMaker AI. Comprehend resuelve un problema específico de NLP mediante una capacidad administrada. SageMaker AI ofrece un entorno mucho más general para construir, entrenar y desplegar modelos propios.

> **Logo** `recursos/aws/ai-ml/comprehend.svg`

> **Idea visual**  
> Icono oficial de **Amazon Comprehend**. Un texto de producto entra y el servicio resalta `Ingredient`, `ProductCode` y otras entidades personalizadas.

## Sesión 15.2 — El modelo lo entrenas tú

### Slide 1 — Amazon SageMaker AI

**Título en slide**

AMAZON SAGEMAKER AI

#### Nombres en portal y examen

> **Amazon SageMaker AI** — anteriormente **Amazon SageMaker**

#### Conceptos

- **Amazon SageMaker AI** permite preparar datos, entrenar modelos de machine learning y desplegarlos para realizar inferencia.
- Encaja cuando necesitas construir o adaptar un modelo para un problema que los servicios especializados no resuelven directamente.
- AWS administra gran parte de la infraestructura utilizada durante entrenamiento y despliegue.
- Un endpoint puede mantener el modelo disponible para que una aplicación solicite predicciones.

> **Nota**  
> No construyas un modelo propio si el requisito ya encaja directamente en Rekognition, Textract, Transcribe, Translate, Polly, Lex o Comprehend.

> **Logo** `recursos/aws/ai-ml/sagemaker.svg`

## Sesión 15.3 — Arquitectura, una imagen al llegar

### Slide 1 — Objeto, función y Rekognition

**Título en slide**

ARQUITECTURA, OBJETO, FUNCIÓN, REKOGNITION

#### Conceptos

- Un nuevo objeto en Amazon S3 genera un evento.
- El evento invoca una función AWS Lambda.
- Lambda utiliza su execution role para solicitar el análisis de la imagen a Amazon Rekognition.
- El resultado se guarda en un destino de la aplicación sin necesidad de entrenar ni mantener un modelo propio.

> **Nota**  
> Esta arquitectura utiliza un servicio AI ya preparado. Amazon SageMaker AI no aparece porque el requisito se resuelve directamente con Rekognition.

> **Idea visual**
>
> 1. Un `PUT` llega al icono oficial de **Amazon S3**.
> 2. El evento invoca el icono oficial de **AWS Lambda**.
> 3. Lambda llama al icono oficial de **Amazon Rekognition** mediante su execution role.
> 4. El resultado vuelve a un prefijo del mismo bucket.
> 5. No dibujar también DynamoDB en esta versión para mantener un único flujo de salida.
> 6. Amazon SageMaker AI no aparece.

1. A global media agency is developing a cultural analysis project to explore how major sports stories have evolved over the last five years. The team has collected thousands of archived news bulletins and magazine spreads stored as PDFs. These documents are rich in unstructured text and come from various sources, with layouts and font styles that differ. The agency wants a clearer picture of how public tone and narrative have shifted over time. The team has chosen Amazon Textract because it can accurately extract printed and scanned text from complex PDF layouts. They need a solution that can then analyze the emotional tone and subject matter of the extracted text with the least possible operational burden, using fully managed AWS services where possible.

Which solution will best meet these requirements?

A) Process the extracted output with AWS Lambda to convert the text into CSV format. Query the data with Amazon Athena and visualize it with Amazon QuickSight.

B) Ingest the extracted data into Amazon Redshift with AWS Glue, and use Amazon Rekognition to analyze the tone of the document layouts for sentiment classification.

C) Send the extracted text to Amazon Comprehend for entity detection and sentiment analysis. Store the results in Amazon S3 so they can be accessed or visualized later.

D) Use Amazon SageMaker to train a custom sentiment analysis model. Store the model outputs in Amazon DynamoDB so analysts can query them in a structured way

✅ **Respuesta** C

💡 **Explanation**  
Amazon Textract extracts the text and document structure, while **Amazon Comprehend** can analyze that extracted text for sentiment and entities using a fully managed NLP service. This avoids the additional operational work of training and maintaining a custom SageMaker AI model when the required capabilities already exist in Comprehend.

2. A digital catalog of consumer products submitted by third-party sellers is managed by an e-commerce company. For each product submission, a description is stored as a text file in an Amazon S3 bucket. Ingredient information for consumable products such as snacks, supplements, or beverages may appear in these descriptions. The company wants a fully automated solution that extracts ingredient names from the uploaded product descriptions and then uses those names to query an Amazon DynamoDB table that returns precomputed health and safety scores for each ingredient. Non-food items and invalid submissions can be ignored, and doing so must not affect application logic. With no in-house machine learning (ML) experts, the company is looking for the most cost-effective solution that also keeps operational overhead to a minimum.

Which solution meets these requirements MOST cost-effectively?

A) Create a workflow that uses Amazon Transcribe to turn synthetic audio versions (created from the text of the product descriptions) back into text. Analyze the transcripts manually or with simple keyword matching inside a Lambda function. For each processed file, use Amazon SNS to notify the content moderation team

B) Whenever a new product description is uploaded, configure S3 Event Notifications to trigger an AWS Lambda function. Inside that function, extract ingredient names with Amazon Comprehend's custom entity recognition feature. Store those names in the DynamoDB table so the front-end application can query for health scores

C) Scan the uploaded text files in the S3 bucket with Amazon Lookout for Vision and extract entities. Invoke this workflow with an S3-triggered Lambda function. Parse the output and push updates to the frontend in real time through Amazon API Gateway

D) Identify ingredients in the uploaded descriptions with Amazon SageMaker and a custom-trained NLP model. Invoke a Lambda function through Amazon EventBridge so it forwards the document content to a SageMaker endpoint and stores the results in DynamoDB. Fine-tune the model with labeled ingredient datasets from open-source repositories and retrain it monthly

✅ **Respuesta** B

💡 **Explanation**  
**Amazon Comprehend Custom Entity Recognition** can identify domain-specific entities such as ingredient names without requiring the company to build and operate a general-purpose NLP model in SageMaker AI. Amazon S3 can trigger Lambda when the description arrives, and the function can invoke the custom recognizer and use the extracted names to work with DynamoDB.

> **Banco** EN — D3_high_performance — id 4
