## Sesión 9.1 — El objeto

### Slide 1 — Amazon S3

**Título en slide —** AMAZON SIMPLE STORAGE SERVICE (AMAZON S3)

#### Nombres en portal y examen

> **Amazon Simple Storage Service (Amazon S3)** — **bucket** — **object**

#### Conceptos

- **Amazon S3 —** almacenamiento de objetos administrado.
- **Objeto —** datos más metadatos identificados mediante una key dentro de un bucket.
- **Region —** el bucket se crea en una AWS Region.
- **Durabilidad —** S3 está diseñado para ofrecer **99.999999999 %**, once nueves, de durabilidad.
- **Block Public Access —** los cuatro controles están habilitados por defecto en buckets nuevos.

> **Nota —** Durabilidad y disponibilidad no son lo mismo. Una storage class puede conservar once nueves de durabilidad y ofrecer menor disponibilidad o resiliencia que otra.

**Docs —** Amazon S3 User Guide — What is Amazon S3?  
**Docs —** Amazon S3 User Guide — Blocking public access

**Idea visual —** icono oficial de **Amazon S3** como elemento central. Un bucket regional contiene tres objetos con keys como `imagenes/logo.png`, dejando claro que los prefijos no son carpetas físicas reales.

### Slide 2 — Acceso frecuente e infrecuente

**Título en slide —** STANDARD — INTELLIGENT-TIERING — IA

#### Nombres en portal y examen

> **S3 Standard** — **S3 Intelligent-Tiering** — **S3 Standard-IA** — **S3 One Zone-IA** — **S3 Express One Zone**

#### Conceptos

- **S3 Standard —** datos consultados con frecuencia y acceso en milisegundos.
- **Intelligent-Tiering —** mueve datos automáticamente entre access tiers cuando el patrón cambia o es impredecible.
- **Standard-IA —** datos consultados con poca frecuencia, pero que todavía necesitan acceso en milisegundos.
- **One Zone-IA —** menor coste porque almacena los datos en una sola Availability Zone.
- **Express One Zone —** almacenamiento S3 de una sola AZ optimizado para workloads sensibles a latencia y altas tasas de requests.

> **Nota —** Standard-IA y One Zone-IA tienen un mínimo de almacenamiento de **30 días** y un tamaño mínimo facturable de **128 KB**. One Zone-IA no es apropiado para la única copia de datos que no pueden reconstruirse.

**Docs —** Amazon S3 User Guide — Understanding and managing S3 storage classes

**Idea visual —** icono oficial de **Amazon S3** arriba. Debajo, cinco bloques — `Standard`, `Intelligent-Tiering`, `Standard-IA`, `One Zone-IA` y `Express One Zone`. Las clases de una sola AZ aparecen claramente marcadas.

### Slide 3 — Archivo

**Título en slide —** S3 GLACIER STORAGE CLASSES

#### Nombres en portal y examen

> **S3 Glacier Instant Retrieval** — **S3 Glacier Flexible Retrieval** — **S3 Glacier Deep Archive**

#### Conceptos

- **Glacier Instant Retrieval —** datos de archivo poco consultados que todavía necesitan recuperación en milisegundos.
- **Glacier Flexible Retrieval —** archivos que pueden esperar minutos u horas para recuperarse.
- **Glacier Deep Archive —** archivo de largo plazo con el menor coste de almacenamiento y recuperación en horas.
- **Retención mínima —** Instant Retrieval y Flexible Retrieval tienen mínimo de **90 días**. Deep Archive tiene mínimo de **180 días**.

> **Nota —** Los objetos en Glacier Flexible Retrieval y Deep Archive permanecen siendo objetos de Amazon S3, pero deben **restaurarse** antes de poder leerse. Glacier Instant Retrieval no necesita restore.

**Docs —** Amazon S3 User Guide — S3 Glacier storage classes  
**Docs —** Amazon S3 User Guide — Working with archived objects

**Idea visual —** icono oficial de **Amazon S3** y tres niveles de archivo. `Instant` muestra milisegundos, `Flexible` minutos u horas y `Deep Archive` almacenamiento de largo plazo.

### Slide 4 — Lifecycle

**Título en slide —** S3 LIFECYCLE

#### Nombres en portal y examen

> **S3 Lifecycle**

#### Conceptos

- **Transition —** cambia automáticamente un objeto hacia otra storage class después del tiempo definido.
- **Expiration —** puede eliminar objetos o versiones cuando cumplen una condición de edad.
- **Filtro —** una regla puede aplicarse según prefix, tags u otras condiciones.
- **No es una storage class —** Lifecycle es la regla que administra el ciclo del objeto.

> **Nota —** Lifecycle sigue rutas de transición compatibles. No se utiliza para volver simplemente un objeto archivado a S3 Standard. Para datos archivados en Flexible Retrieval o Deep Archive primero debes restaurar el objeto y luego copiarlo si necesitas una copia permanente en otra clase.

**Idea visual —** icono oficial de **Amazon S3** con una línea temporal — `Día 0 Standard → Día 30 Standard-IA → Día 180 Deep Archive → Expire`.

### Slide 5 — Storage Class Analysis

**Título en slide —** STORAGE CLASS ANALYSIS

#### Conceptos

- **Análisis —** observa patrones de acceso de objetos almacenados en S3 Standard.
- **Recomendación —** ayuda a decidir cuándo pasar datos desde Standard hacia Standard-IA.
- **No mueve datos —** el resultado sirve para diseñar o mejorar una Lifecycle rule.
- **Filtro —** puede analizar todo el bucket o grupos definidos por prefix y tags.

> **Nota —** Storage Class Analysis recomienda específicamente transiciones **Standard → Standard-IA**. No recomienda transiciones hacia One Zone-IA o las clases Glacier.

**Docs —** Amazon S3 User Guide — Storage Class Analysis

## Sesión 9.2 — Copia y candado

### Slide 1 — AWS DataSync

**Título en slide —** AWS DATASYNC

#### Nombres en portal y examen

> **AWS DataSync**

#### Conceptos

- **AWS DataSync —** servicio administrado para mover datos entre almacenamiento on-premises, AWS y otros destinos compatibles.
- **Hacia S3 —** puede copiar archivos desde un datacenter hacia un bucket Amazon S3.
- **Archivo —** después puedes utilizar una Lifecycle rule para mover esos objetos a una storage class de archivo.
- **Deep Archive —** es una storage class de Amazon S3, no un “Glacier Deep Archive vault” independiente.

> **Nota —** En el banco del módulo, el patrón es **DataSync → S3 → Lifecycle → S3 Glacier Deep Archive** para conservar backups a muy bajo coste.

**Docs —** AWS DataSync User Guide — Transfers with Amazon S3

### Slide 2 — Versioning

**Título en slide —** S3 VERSIONING

#### Nombres en portal y examen

> **S3 Versioning**

#### Conceptos

- **Versioning —** conserva múltiples versiones de una misma object key.
- **Overwrite —** una nueva subida genera una versión nueva sin eliminar inmediatamente la anterior.
- **Delete —** normalmente crea un delete marker en lugar de borrar permanentemente versiones anteriores.
- **Suspender —** después de habilitar versioning, el bucket puede pasar a `Suspended`, pero no vuelve al estado original `Unversioned`.

> **Nota —** Versioning es requisito para utilizar S3 Replication y S3 Object Lock.

**Docs —** Amazon S3 User Guide — Using versioning in S3 buckets

**Idea visual —** icono oficial de **Amazon S3** con un objeto `foto.jpg` y tres versiones — `v1`, `v2`, `v3`.

### Slide 3 — CRR y SRR

**Título en slide —** CRR — SRR — BATCH REPLICATION

#### Nombres en portal y examen

> **Cross-Region Replication (CRR)** — **Same-Region Replication (SRR)** — **S3 Batch Replication**

#### Conceptos

- **CRR —** replica objetos hacia un bucket situado en otra AWS Region.
- **SRR —** replica hacia otro bucket de la misma Region.
- **Versioning —** debe estar habilitado en source y destination.
- **Nuevos objetos —** la replication rule se aplica a objetos elegibles después de configurarla.
- **Objetos existentes —** S3 Batch Replication permite replicarlos posteriormente.

> **Nota —** El destination bucket debe existir antes de configurar la replication rule. Para una copia puntual también puedes utilizar herramientas de copia como `aws s3 sync`; no confundas una copia manual con replicación continua.

**Docs —** Amazon S3 User Guide — Replicating objects  
**Docs —** Amazon S3 User Guide — S3 Batch Replication

**Idea visual —** icono oficial de **Amazon S3** en dos Regions. Una flecha `CRR` cruza entre Regions. Debajo, dos buckets de una misma Region unidos mediante `SRR`.

### Slide 4 — Object Lock

**Título en slide —** S3 OBJECT LOCK

#### Nombres en portal y examen

> **S3 Object Lock** — **WORM** — **Governance mode** — **Compliance mode**

#### Conceptos

- **WORM —** Write Once, Read Many. Protege una versión frente a eliminación o sobrescritura durante un periodo.
- **Governance —** usuarios con permisos especiales pueden omitir la retención.
- **Compliance —** la versión protegida no puede eliminarse antes de vencer la retención, ni siquiera por el root user.
- **Versioning —** Object Lock trabaja con buckets versionados.

> **Nota —** Object Lock puede utilizar un retention period o un legal hold. No es lo mismo que MFA Delete.

**Docs —** Amazon S3 User Guide — S3 Object Lock

**Idea visual —** icono oficial de **Amazon S3** con un objeto y un candado `WORM`. Dos etiquetas — `Governance` con una llave administrativa y `Compliance` con un candado que no puede abrirse antes de la fecha.

### Slide 5 — MFA Delete

**Título en slide —** MFA DELETE

#### Nombres en portal y examen

> **MFA Delete**

#### Conceptos

- **MFA —** exige autenticación adicional para eliminar permanentemente una object version o cambiar el estado de versioning.
- **Root —** solo el bucket owner autenticado como root user puede habilitar MFA Delete.
- **Versioning —** debe estar habilitado para poder utilizarlo.
- **No es retención —** no impide borrar hasta una fecha concreta.

> **Nota —** MFA Delete no puede habilitarse desde la AWS Management Console. Se configura mediante CLI o API.

**Docs —** Amazon S3 User Guide — Configuring MFA Delete

**Idea visual —** icono oficial de **Amazon S3** con una object version. Antes de `Permanent Delete`, aparece un segundo factor MFA asociado al root user.

## Sesión 9.3 — Acceso

### Slide 1 — Cifrado en Amazon S3

**Título en slide —** SSE-S3 — SSE-KMS — SSE-C

#### Nombres en portal y examen

> **SSE-S3** — **SSE-KMS** — **SSE-C** — **client-side encryption**

#### Conceptos

- **SSE-S3 —** Amazon S3 administra las encryption keys y es el cifrado por defecto de todos los objetos nuevos.
- **SSE-KMS —** utiliza AWS KMS y permite mayor control de keys, permisos y auditoría.
- **S3 Bucket Keys —** reducen las llamadas de S3 hacia AWS KMS y pueden reducir su coste.
- **SSE-C —** tú proporcionas la encryption key en cada request y AWS no almacena esa key.
- **Client-side —** los datos se cifran antes de enviarse a Amazon S3.

> **Nota —** Desde abril de 2026, SSE-C está deshabilitado por defecto para nuevos general purpose buckets. Un workload que todavía lo necesite debe habilitarlo deliberadamente. AWS KMS se estudia en M17.

**Docs —** Amazon S3 User Guide — Default encryption  
**Docs —** Amazon S3 User Guide — Server-side encryption with customer-provided keys

**Idea visual —** icono oficial de **Amazon S3** frente a tres llaves — `SSE-S3 — S3`, `SSE-KMS — M17` y `SSE-C — Customer`. Al lado, un archivo cifrado antes de subir representa client-side encryption.

### Slide 2 — SSE-KMS y replication

**Título en slide —** SSE-KMS EN REPLICATION

#### Conceptos

- **Opt-in —** los objetos SSE-KMS deben incluirse explícitamente en la replication configuration.
- **Permisos —** el replication role necesita permisos sobre las KMS keys correspondientes.
- **Destination key —** defines la KMS key que cifrará las replicas en el destination bucket.
- **Cross-Region —** la destination KMS key debe existir en la Region de destino.

> **Nota —** No es obligatorio utilizar una **multi-Region KMS key**. Amazon S3 admite esas keys, pero actualmente las trata como keys regionales para este propósito.

**Docs —** Amazon S3 User Guide — Replicating encrypted objects

### Slide 3 — Presigned URL

**Título en slide —** PRESIGNED URL

#### Nombres en portal y examen

> **Presigned URL**

#### Conceptos

- **Acceso temporal —** permite descargar o subir un objeto sin entregar credenciales AWS al usuario final.
- **Permiso heredado —** la URL utiliza los permisos del principal que la firma.
- **IAM user —** con Signature Version 4 puede tener una expiración máxima de **7 días** mediante CLI o SDK.
- **Temporary credentials —** la URL deja de funcionar cuando expiran esas credenciales, aunque se haya configurado una duración mayor.

> **Nota —** Una presigned URL no hace público el bucket ni crea una identidad nueva.

### Slide 4 — Bucket y object ARN

**Título en slide —** BUCKET ARN NO ES OBJECT ARN

#### Nombres en portal y examen

> **s3:ListBucket** — **s3:GetObject** — **s3:DeleteObject**

#### Conceptos

- **Bucket action —** `s3:ListBucket` utiliza el ARN del bucket.
- **Object actions —** `s3:GetObject` y `s3:DeleteObject` utilizan un ARN de objetos.
- **Bucket ARN —** `arn:aws:s3:::mybucket`
- **Objects ARN —** `arn:aws:s3:::mybucket/*`

```text
ListBucket
arn:aws:s3:::mybucket

GetObject / DeleteObject
arn:aws:s3:::mybucket/*
```

> **Nota —** Esta diferencia de ARN aparece directamente en preguntas de IAM para Amazon S3.

**Idea visual —** icono oficial de **Amazon S3**. Un contorno representa el bucket y recibe `ListBucket`. Dentro hay objetos y únicamente ellos reciben `GetObject / DeleteObject`.

### Slide 5 — Bucket policy y Object Ownership

**Título en slide —** BUCKET POLICY — OBJECT OWNERSHIP

#### Nombres en portal y examen

> **Bucket policy** — **S3 Object Ownership** — **Bucket owner enforced**

#### Conceptos

- **Bucket policy —** resource-based policy asociada al bucket.
- **Cross-account —** puede autorizar principals de otra AWS account.
- **Bucket owner enforced —** configuración predeterminada de Object Ownership en buckets nuevos.
- **ACLs disabled —** con ese modo, las ACL dejan de controlar permisos.
- **Ownership —** el bucket owner posee automáticamente los objetos, incluso si otra cuenta los sube.

> **Nota —** El comportamiento moderno ya no es “el uploader siempre es dueño del objeto”. Con **Bucket owner enforced**, el bucket owner controla todos los objetos mediante policies.

**Docs —** Amazon S3 User Guide — S3 Object Ownership

### Slide 6 — Exigir cifrado

**Título en slide —** BUCKET POLICY — DENY SIN CIFRADO REQUERIDO

#### Conceptos

- Una bucket policy puede utilizar un **explicit Deny** para rechazar uploads que no cumplan el cifrado exigido.
- El requisito puede obligar, por ejemplo, a utilizar una determinada configuración SSE-KMS.
- El `Deny` de la bucket policy prevalece cuando sus condiciones se cumplen.
- El cifrado SSE-S3 por defecto no sustituye una política que exige específicamente otro método.

> **Nota —** Aquí reutilizamos la lógica de explicit deny aprendida en M3.

**Idea visual —** icono oficial de **Amazon S3**. Un `PutObject` con el requisito de cifrado correcto entra; otro request sin la configuración requerida choca contra un `Explicit Deny`.

### Slide 7 — S3 Event Notifications

**Título en slide —** S3 EVENT NOTIFICATIONS

#### Nombres en portal y examen

> **S3 Event Notifications**

#### Conceptos

- Un evento como `ObjectCreated` puede producir una notificación.
- S3 puede enviar notificaciones directamente hacia **Amazon SNS**, una **Amazon SQS Standard queue** o **AWS Lambda**.
- También puede enviar eventos hacia **Amazon EventBridge**.
- Una SQS FIFO queue no puede ser destino directo de una S3 event notification.

> **Nota —** Si necesitas llevar un evento S3 hacia una SQS FIFO queue, puedes hacerlo mediante Amazon EventBridge. Los servicios de mensajería se estudian más adelante.

**Docs —** Amazon S3 User Guide — Amazon S3 Event Notifications

**Idea visual —** icono oficial de **Amazon S3** recibe un nuevo objeto. Sale una campana hacia tres destinos en gris — `SNS`, `SQS Standard` y `Lambda`. Una ruta adicional pasa por `EventBridge → SQS FIFO`.

### Slide 8 — Static Website Hosting

**Título en slide —** STATIC WEBSITE HOSTING

#### Nombres en portal y examen

> **Static website hosting** — **website endpoint**

#### Conceptos

- Un bucket puede servir archivos estáticos como `index.html`.
- El website endpoint de Amazon S3 utiliza **HTTP**, no HTTPS.
- Para un sitio público servido directamente desde ese endpoint, los objetos deben ser públicamente legibles.
- Con un dominio personalizado y el patrón tradicional de S3 website, el nombre del bucket se alinea con el dominio.

> **Nota —** Para HTTPS y un bucket privado, el patrón moderno utiliza Amazon CloudFront con acceso controlado al origen. Eso se estudia en M10.

### Slide 9 — Multipart Upload

**Título en slide —** MULTIPART UPLOAD

#### Nombres en portal y examen

> **Multipart upload**

#### Conceptos

- Un objeto grande se divide en partes que se suben de forma independiente.
- Las partes pueden cargarse en paralelo para mejorar throughput.
- Si una parte falla, solo necesitas volver a subir esa parte.
- AWS recomienda considerar multipart upload desde aproximadamente **100 MB**.

> **Nota —** Para cargas del orden de cientos de GB o TB, multipart upload es el patrón natural.

**Docs —** Amazon S3 User Guide — Uploading objects using multipart upload

**Idea visual —** icono oficial de **Amazon S3**. Un archivo grande se divide en cuatro partes. Una parte falla y solo esa muestra una flecha de reintento.

### Slide 10 — Transfer Acceleration

**Título en slide —** S3 TRANSFER ACCELERATION

#### Nombres en portal y examen

> **S3 Transfer Acceleration**

#### Conceptos

- **Larga distancia —** utiliza AWS edge locations para acelerar transferencias hacia y desde un bucket.
- **Endpoint —** utiliza el dominio `s3-accelerate.amazonaws.com`.
- **Uso —** clientes geográficamente lejanos que transfieren objetos hacia una Region.
- **Coste —** AWS cobra la aceleración únicamente cuando puede aportar una mejora de rendimiento.

> **Nota —** Transfer Acceleration mejora la ruta de transferencia. No cambia la storage class ni sustituye multipart upload; ambos pueden utilizarse juntos.

**Docs —** Amazon S3 User Guide — S3 Transfer Acceleration

### Slide 11 — Request performance

**Título en slide —** REQUEST RATE POR PREFIX

#### Conceptos

- Amazon S3 escala automáticamente para cargas de requests elevadas.
- Un prefix puede soportar al menos **3 500 PUT/COPY/POST/DELETE por segundo**.
- Un prefix puede soportar al menos **5 500 GET/HEAD por segundo**.
- Utilizar varios prefixes permite escalar el throughput de requests todavía más.

> **Nota —** Ya no necesitas randomizar los nombres de las keys para obtener rendimiento. Si la aplicación sostiene tasas muy superiores, distribuye requests y escala gradualmente.

**Docs —** Amazon S3 User Guide — Optimizing Amazon S3 performance

**Idea visual —** icono de **Amazon S3** con tres prefixes — `/a`, `/b`, `/c`. Cada uno recibe requests en paralelo.

### Slide 12 — CORS

**Título en slide —** CORS

#### Nombres en portal y examen

> **Cross-Origin Resource Sharing (CORS)**

#### Conceptos

- Un navegador puede solicitar un recurso S3 desde una página cargada desde otro origin.
- CORS define qué origins, métodos y headers están permitidos por el navegador.
- Sin la configuración adecuada, el navegador puede bloquear la respuesta.
- CORS no concede permisos de IAM.

> **Nota —** Primero debe existir autorización para acceder al objeto. CORS controla si el navegador permite utilizar esa respuesta desde otro origin.

**Idea visual —** navegador en `app.ejemplo.com` solicita un objeto de S3. Una barrera `CORS` se abre únicamente para el origin permitido.

### Slide 13 — S3 Access Points

**Título en slide —** S3 ACCESS POINTS

#### Nombres en portal y examen

> **S3 Access Point**

#### Conceptos

- **Access Point —** endpoint con nombre propio asociado a un bucket.
- **Policy propia —** cada access point puede tener permisos específicos para una aplicación o conjunto de datos.
- **Network origin —** puede restringirse para acceso desde una VPC.
- **Escala —** simplifica el acceso cuando varias aplicaciones utilizan el mismo bucket con necesidades diferentes.

> **Nota —** El bucket sigue siendo uno. Los Access Points proporcionan entradas separadas con controles de acceso independientes.

**Docs —** Amazon S3 User Guide — Managing access with S3 Access Points
